# Правила Excel-реестра

## Новая книга

- Основная таблица с первой строки: шапка, затем данные без пустых разделителей. Нужные вводные вынеси на отдельный лист.
- Шапка синяя (`#4472C4`), белый полужирный текст; белые строки, тёмный текст, тонкие границы (`#8FAADC`). Ориентир шрифта Arial 10–11. При существующем формате пользователя сохраняй его.
- Коды храни текстом. Колонки кодов узкие, названия средние, вопрос/ответ/требование широкие. Перенос текста и высота строк должны позволять читать вопрос полностью; слишком высокие строки разделяй по смыслу.
- Закрепи строку шапки; нужные колонки слева закрепляй так, чтобы не занять весь экран. Не объединяй ячейки и не добавляй декоративные заголовки внутри фильтра.
- Используй таблицу Excel с уникальным именем и фильтрами. Если инструмент поддерживает только обычный автофильтр, допустим диапазон с фильтром, но укажи его тип при необходимости; не называй его нативной таблицей Excel.
- Не включай полосатый стиль, сводные диаграммы и дополнительное оформление без цели. Объём строк определяется содержанием интервью.

## Обновление

После добавления строк расширь диапазон таблицы, её автофильтра и обычного автофильтра листа, если последний применяется к тому же реестру. Если на листе несколько независимых таблиц, меняй только нужную.

Последнюю строку определяй по реальным данным процесса/вопроса. `max_row` или `dimension` могут учитывать лишь форматирование далеко под таблицей. Примечания за таблицей не превращай в строки процессов автоматически.

Если есть фильтрующие условия, сохраняй их, пока задача не требует сброса. Отличай строку за пределами диапазона от строки, скрытой действующим условием. Фильтр по колонке «Блок»/L1 должен видеть все фактические значения, включая добавленные блоки ЭДО/Диадок.

При сохранении столбцов владельцев, ответов и требований проверь соответствие старому процессу, а не только той же позиции строки. Текст вопросов может уточняться; ответы должны оставаться связанными с тем вопросом, на который были даны.

## Итоговые проверки

1. Иерархия содержит три пары «код — название»; на всех уровнях номер отделён от названия.
2. У каждого кода неизменные родители и название; повтор L3 для нескольких вопросов допустим.
3. Вопросы пользователя, их существенные условия, ответы и принятые решения сохранены.
4. Диапазон фильтра/таблицы охватывает все строки реестра; новые блоки включены. Прочитанный файл и сохранённый результат не перепутаны.
5. Нет обрезанных длинных вопросов, перекрытия текста, лишних объединений, ошибок формул или неожиданного изменения листов.

Read-only проверка `flow1c_interview` action=`audit` / `scripts/flow1c.py interview-register --json-stdin` покрывает пункты 1, 2 и часть 4 в распознанной схеме. Остальные проверки выполняй по файлу и доступному просмотру. Audit не исправляет выявленные проблемы автоматически; write создаёт проверенную новую копию.
