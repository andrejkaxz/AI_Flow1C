# Куда положить материалы проекта

При подключении проекта Flow1C создаёт в репозитории документации четыре
пользовательские папки и главную страницу `README.md`:

| Папка | Материалы | Запрос агенту |
|---|---|---|
| `Материалы встреч` | Протоколы, заметки, готовые расшифровки, ответы интервью | «Выдели решения, требования и открытые вопросы из этой встречи» |
| `Шаблоны документов` | Исходные DOCX/Markdown-шаблоны и заполненные образцы | «Добавь этот шаблон ТЗ в библиотеку проекта» |
| `Реестр процессов и требований` | Исходный Excel-реестр, отдельные версии файлов | «Импортируй реестр из файла …» |
| `Документы для анализа` | Регламенты, инструкции, схемы процессов, ФС и другие документы | «Изучи эти документы и опиши процесс …» |

Пользователь кладёт файлы в нужную папку и формулирует задачу. Не требуется
знать служебную структуру Flow1C или заранее создавать рабочий элемент.
Названия подпапок и файлов произвольные; у нескольких версий нужно выбрать
актуальную. Для аудио/видео требуется отдельно доступная обработка либо
готовая расшифровка. Поддержка формата проверяется при выполнении операции.

## Обработка агентом

Размещение файла не запускает фоновый анализ или импорт. На явный запрос:

- встреча/документ: принять выбранные материалы через `flow1c_intake` и работать
  с возвращёнными путями, затем использовать ограниченный контекст;
- реестр: выполнить существующий `registry-import` с выбранным Excel;
- шаблон: использовать `flow1c_template` / `template intake` для выбранного
  файла и типа, затем согласовать правила по контракту библиотеки.

Если файл уже находится в документации проекта, не просить пользователя
загрузить его повторно. Попросить выбрать файл/версию только при неоднозначности.
README внутри входных папок — инструкция, не материал анализа и не шаблон.
Не включать их в intake. Название папки помогает выбрать материал, но не
подтверждает тип, качество, approvals или содержимое файла.

Исходники в этих папках сохраняются; принятые копии и provenance находятся
в служебных областях. Наличие файла в `Шаблоны документов` не означает
включение в управляемую библиотеку; Excel во входной папке не заменяет
действующий реестр до успешного импорта. XML/BSL подключаются отдельно,
не складываются в документацию. Результат возвращается с конкретной ссылкой;
Git/PR выполняются в пределах поручения пользователя.

## Источник структуры и совместимость

Начальная структура и содержимое README принадлежат
`templates/project-documentation/`. `scripts/configure-project.ps1` вызывает
`Initialize-Flow1CDocumentation` из `scripts/project-documentation.ps1`, который вызывает Python-сервис
`flow1c.documentation`:
создаёт только отсутствующие Markdown и возвращает их пути для исходного
Git-коммита. Существующие файлы, даже пустые или изменённые пользователем,
не заменяются; symlinks/junctions и конфликт файла с каталогом отклоняются.

Новые проекты хранят служебные области внутри `.flow1c/`; четыре входные
папки и README остаются в корне. Старые проекты без записи версии layout
продолжают использовать прежние пути. Configure и update не переносят данные
существующего проекта. [Версии структуры и совместимость](documentation-layout.md).

`template configure` также создаёт инструкции и выбирает layout для нового
каталога документации; Git и полная настройка проекта для этого не требуются.
Существующие пользовательские файлы и библиотека сохраняются.
