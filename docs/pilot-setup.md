# Пилотная установка через агента

Этот пилот проверяет установку и пользовательский setup версии в разработке.
Успешный setup подтверждает выбранный профиль; полная приёмка поведения моделей
и готовность выпуска проверяются отдельно.

## Отдельный checkout

Выберите новую папку вне workspace разработки Flow1C и выполните:

```powershell
git clone https://github.com/andrejkaxz/AI_Flow1C.git
Set-Location -LiteralPath .\AI_Flow1C
git rev-parse HEAD
```

Запишите commit SHA. Откройте именно эту папку как проект в Codex или Claude Code.
В OpenCode используйте `flow1c-controller` из `opencode.json`.
Не переносите `.venv`, `.workspace`, `.tools` и `.flow1c.local.json` из другой
установки: первый прогон должен начинаться с чистого checkout.

## Запрос агенту

Для рекомендуемого профиля аналитика и архитектора:

> Подготовь проект к работе с профилем analysis. Проведи все шаги setup:
> аудит, согласование путей и плана установки, bootstrap, подключение проекта,
> индексацию и настройку библиотеки шаблонов. Сохрани setup_id для продолжения
> после перезапуска и покажи итог проверки готовности выбранного профиля.

Если хотите проверить также BSL Language Server и `cc-1c-skills`, явно выберите
профиль `full` и отдельно разрешите установку `cc-1c-skills`.
Описание возможностей каждого профиля — в [setup.md](setup.md).

## Что подготовить

- Папку и, при наличии, URL репозитория документации проекта. Для новой локальной
  папки явно разрешите инициализацию Git.
- Пользовательский идентификатор проекта.
- Путь к локальной XML/BSL-выгрузке конфигурации.
- Папку расширения и его режим: Git checkout с URL либо локальная выгрузка.
- При наличии — файлы шаблонов документов и реестр требований.

Документация, конфигурация и расширение находятся в отдельных папках вне Flow1C.
Секреты передаются через предусмотренные переменные окружения или Credential
Manager. Агент сначала показывает результаты аудита и согласует сводный набор
путей/URL, затем точный план установок. Отдельные установки prerequisites и
`cc-1c-skills` выполняются с предусмотренным согласием пользователя.

## Что проверить во время setup

1. Аудит и план отражают отсутствующие компоненты выбранного профиля.
2. Bootstrap создаёт окружение внутри нового checkout и сохраняет завершённые шаги.
3. Подключение проекта сохраняет подтверждённые значения в `.flow1c.local.json`.
   В каталоге документации появляются четыре входные папки с русскими
   названиями и README: [куда положить материалы](project-materials.md).
4. Для `analysis` и старших профилей индексы обоих источников достигают `FRESH`.
   При `WAITING_BACKGROUND` сохраните `setup_id` и продолжите тот же setup.
5. Агент предлагает библиотеку шаблонов; можно принять часть типов или отложить
   их. Пустая библиотека не блокирует setup.
6. Перезапустите клиент и попросите продолжить по сохранённому `setup_id`.
   Неизменившиеся подтверждённые значения и завершённые шаги должны сохраниться.
7. Итоговый `doctor` проверяет выбранный профиль:

```powershell
.\.venv\Scripts\python.exe scripts\flow1c.py doctor --json --profile analysis
```

Для профиля `full` замените значение `--profile`. Если состояние не `READY`,
сохраните конкретные blockers и предложенные действия; не начинайте новый setup
вместо доступного resume. Команды восстановления описаны в [setup.md](setup.md).

## Результат пилота

Сохраните локально commit SHA, клиент и model ID, версии Python/PowerShell/Node,
выбранный профиль, `setup_id`, результаты шагов и итоговый `doctor`.
Полезный отчёт об ошибке содержит ожидаемое и фактическое поведение и способ
воспроизведения. Перед публикацией отчёта удалите секреты, внутренние URL,
пользовательские пути и материалы проекта.

После успешного setup проверьте консультацию и независимый черновик, затем
продолжение прерванного запроса. Правила обновления с сохранением данных — в
[update.md](update.md); модельные сценарии приёмки — в [opencode-evals.md](opencode-evals.md).
