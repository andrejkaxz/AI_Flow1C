# Качество требований

`flow1c-requirements-quality` — вспомогательный навык для создания, уточнения
и ревью требований в протоколах, реестрах и функциональных спецификациях.
Он применяется также при выделении требований из ответов интервью.
Правила и примеры входят в поставку: [навык](../.agents/skills/flow1c-requirements-quality/SKILL.md),
[примеры](../.agents/skills/flow1c-requirements-quality/references/examples.md).

## Применение

Сначала выбирается обычная операция и один основной навык по
[маршрутизации](intent-routing.md). Проверка качества выполняется внутри этого
запроса с теми же инструментами и разрешёнными источниками. Она подключена
из навыков интервью, консультации, реестра, ФС, функционального ревью и
создания документов по шаблону. Отдельной операции и gate для неё нет.

Codex читает канонический файл из `.agents/skills/`; Claude Code использует
обёртку в `.claude/skills/`. OpenCode после begin читает правила через
`flow1c_inspect`, `scope=workflow`,
`path=.agents/skills/flow1c-requirements-quality/SKILL.md`.
Примеры читаются по необходимости из `references/examples.md` того же навыка.
Локальная установка личных навыков автора не требуется.

## Результат проверки

Для каждого требования в порученном объёме фиксируются конкретность,
непротиворечивость, полнота и временные границы. Вердикты: «соответствует»,
«не соответствует», «недостаточно данных»; неприменимость временной оси
требует обоснования. Время поведения, период применимости и срок поставки
рассматриваются отдельно. Неизвестные сроки и другие параметры остаются
открытыми вопросами.

Сохраняются исходные формулировки, ID, точные версии и локаторы источников.
Значимые фрагменты источника сопоставляются с требованиями, фактами, решениями,
поручениями, вопросами или рисками. Для замечаний учитываются также комментарии
и содержательные исправления; обычное извлечение текста Word может их потерять.
При отсутствии разрешённого средства чтения таких данных указывается предел
проверки. Структурный audit и визуальная проверка документа остаются отдельными
проверками соответствующего формата.

Качество ведётся отдельно от согласования. «Готово к согласованию» не означает
«согласовано», принятия результата или типовой поддержки в 1С. Навык не меняет
формат реестра, ID из колонки J, approvals, prerequisites и статус черновика.
При нехватке полей результат проверки сохраняется в совместимом сопроводительном
разделе или таблице. Исходник редактируется только в порученном объёме.

Для простого импорта, проверки структуры и форматирования без анализа содержания
требований этот навык не применяется. Проверка основана на прочитанных источниках
и работе агента; это не новый автоматический валидатор CLI.
