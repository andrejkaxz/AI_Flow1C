# Подготовка интервью для обследования 1С

Сценарий помогает составить реестр процессов, вопросов и требований при
внедрении 1С:ERP, 1С:ERP. Управление холдингом и 1С:Управление холдингом.
Методика перенесена из предоставленного комплекта «Подготовка к интервью»;
исходная папка не нужна для установки и использования продукта.

## Как попросить агента

```text
Подготовь интервью с заказчиком для перехода с текущей системы на 1С:ERP.
Блоки: закупки и склад. Продажи рассматриваем только на границе передачи данных.
Заказчик, партнёр и известные сведения: [текст или файлы].
Составь Excel-реестр процессов трёх уровней и вопросов.
Отдели коды от названий. Добавь владельца, исполнителя, ответ,
решение, требование и критерий приёмки. Неизвестное пометь «Уточнить».
```

```text
Расширь приложенный реестр вопросами по возвратам и ЭДО.
Сохрани существующие коды, ответы, комментарии и оформление.
Сделай новую копию; новые вопросы не должны повторять уже заданные.
```

```text
Из ответов заказчика выдели требования с критериями приёмки.
Сохрани связь с процессом, вопросом и исходным ответом.
Противоречия и неподтверждённые решения вынеси на согласование.
```

Достаточно вводных в чате; [анкета](../.agents/skills/flow1c-interview-preparation/assets/project-brief.md)
необязательна. Агент уточняет следующий существенный выбор и продолжает
независимые части. Подготовка к собеседованию на работу — другой сценарий.

## Результат и границы

Основной лист содержит три пары «код — название», «Что уточняем на интервью»,
владельца, участника, исходный ответ, требование/критерий, ID вопроса,
нормализованное решение и источник/исходный номер вопроса. Код L3 может
повторяться для разных вопросов одного процесса, а ID вопроса уникален.
Коды сохраняются как текст; нумерация существующих процессов не меняется.

Листы «FLOW1C Контекст», «FLOW1C Требования», «FLOW1C Источники», «FLOW1C Открытые вопросы»
сохраняют вводные, прослеживаемость и ограничения. При обновлении старые
листы сохраняются, для новых сведений добавляются отдельные листы с суффиксом.
Новый лист требований содержит требования, переданные в текущем запросе,
а не автоматически объединённый набор всех ранее предложенных требований.

Вся книга имеет статус `UNVERIFIED_DRAFT`; `draft_id` — локальная ссылка на
черновое требование, а не ID формального реестра. Вопрос без ответа остаётся
вопросом; требование должно ссылаться на сохранённый ответ. Статусы новых
требований — «Черновик» или «Требует согласования».

Книга интервью **не является формальным реестром Flow1C**: в существующем
registry-import ID требования читается из колонки J, а здесь J содержит ответ.
Не импортируйте её напрямую. Переход к формальным требованиям требует
отдельного согласованного сопоставления, назначения авторитетных ID в проектном
реестре и его обычной проверки `flow1c-registry`. Номера задач агент не придумывает.

## Общий протокол клиентов

Codex загружает `.agents/skills/flow1c-interview-preparation/SKILL.md`, Claude Code
использует обёртку `.claude/skills/flow1c-interview-preparation/SKILL.md`, OpenCode
выбирает тот же primary и инструмент `flow1c_interview`. Доменные правила едины.

1. `doctor --json --operation interview-preparation` проверяет Python, skill и
   openpyxl, без настроенной конфигурации, Git проекта и RLM. Для установки
   зависимостей после согласия: `bootstrap.ps1 -Profile documents`; автоматически
   сеть и системные зависимости не меняются. Без Excel можно готовить Markdown.
   Для такого формата: `doctor --json --operation interview-preparation --format markdown`.
2. `agent-begin`: operation=`interview-preparation`, mode=`draft` (по умолчанию).
   Для совета/просмотра без записи — `explore`. Formal для этого сценария запрещён.
3. Если книга уже есть, `artifact-intake` / `flow1c_intake`; используйте `copied[].path`.
   `flow1c_interview inspect` возвращает строки с `offset`, `limit` (1–200) и
   `next_offset`; прочитайте все относящиеся к обновлению строки и контекст.
4. `flow1c_interview write` → `audit`. Каждая запись создаёт новый файл в draft
   текущего запроса, без перезаписи исходника. Одинаковые входы повторно
   возвращают тот же неизменённый результат; для новой редакции другое имя.
5. `flow1c_complete` с output последней книги проверяет SHA-256 и структуру,
   возвращает `DRAFT_COMPLETE`. Для Markdown используйте `flow1c_write` и обычное
   завершение черновика; для explore — summary и `CONSULTATION_COMPLETE`.

Каталог результатов: `<documentation_path>/drafts/<request-id>/`, если путь
настроен; иначе `.workspace/drafts/<request-id>/`. Обязательных внешних папок
`outputs/` и `work/` нет. Контекст запроса, ответы и evidence сохраняются рядом.

## Контракт CLI и OpenCode

В CLI вызывайте `scripts/flow1c.py interview-register --json-stdin` из корня
workflow, передавая JSON через stdin. OpenCode передаёт тот же объект request
строкой в `flow1c_interview.request_json` плюс gate_id и action. Контракт версии 1:
[interview-register.schema.json](../schemas/interview-register.schema.json).

Новая книга (бизнес-правила ниже только пример; не факт о заказчике):

```json
{
  "gate_id": "<ID из agent-begin>",
  "action": "write",
  "request": {
    "output_name": "interview-v1.xlsx",
    "context": {"Целевая система": "Уточнить", "Границы": "Закупки; склад"},
    "rows": [{
      "l1_code": "01", "l1_name": "Закупки",
      "l2_code": "01.01", "l2_name": "Управление поставщиками",
      "l3_code": "01.01.01", "l3_name": "Создание и учёт поставщиков",
      "question_id": "Q-0001",
      "question": "Кто создаёт поставщика, как проверяются дубли и кто утверждает сведения?",
      "owner": "Уточнить", "interviewer": "Уточнить",
      "answer": "", "decision": "", "requirement": "",
      "source": "Вводные пользователя, вопрос 1"
    }],
    "open_questions": ["Уточнить продукт и релиз; типовые механизмы пока не проверены."]
  }
}
```

Обновление принятой/записанной книги:

```json
{
  "gate_id": "<ID текущего запроса>",
  "action": "write",
  "request": {
    "source": "interview-v1.xlsx",
    "sheet": "Реестр",
    "output_name": "interview-v2.xlsx",
    "rows": [],
    "patches": [{"question_id": "Q-0001", "fields": {
      "answer": "Ответ заказчика: перед сохранением нужно проверять совпадение ИНН.",
      "decision": "Проверка совпадения ИНН; действие при совпадении уточнить."
    }}],
    "requirements": [{
      "draft_id": "DRAFT-1", "question_id": "Q-0001",
      "text": "Перед сохранением поставщика проверять наличие совпадающего ИНН.",
      "acceptance_criterion": "При совпадении проверка обнаруживает запись; дальнейшее действие уточнить.",
      "status": "Требует согласования", "implementation": "Требует проверки"
    }]
  }
}
```

`rows` добавляет вопросы. `patches` меняет только `owner`, `interviewer`, `answer`,
`decision`, `requirement`, `source` по ID вопроса; неизменённые поля сохраняются.
Менять через patches код, название, вопрос и ID запрещено, чтобы не отделить
ответ от первоначального вопроса. При смене смысла нужен отдельный план
сопоставления. Содержимое новых ячеек — текст, даже если начинается с `=`.
Формулы исходной книги сохраняются и не заменяются текстом правок.

`sources`: список объектов со строками `id`, `location`, `section`,
`product_release`, `checked_at`, `availability`, `conclusion`, `related_questions`.
Для source принимаются только пути из текущего intake или записанного evidence,
с совпадающим SHA-256. Предыдущую версию из другого запроса сначала примите
через intake. В старой распознанной книге без ID вопросов inspect показывает
локальные предварительные IDs; write добавляет их только в новую копию.

## Проверки и ограничения

Адаптер перечитывает сохранённый файл: проверяет три уровня, единство имён и
родителей кода, уникальность вопросов/ID, связь требования с ответом, отсутствие
пустых строк внутри данных, охват таблицы и автофильтров. Скрытые строки отмечает
предупреждением, условия фильтра не сбрасывает. Визуальное оформление,
смысловые повторы и полноту обследования проверяет агент отдельно; вычисление
формул и проверка в базе 1С не выполняются.

Поддерживаются обычные XLSX с распознаваемой шапкой, одной таблицей на листе
реестра, без строки итогов и объединённых ячеек. Пределы: 10 000 строк,
100 колонок, 25 MiB исходной книги, 100 MiB распакованного OOXML. Книги с
рисунками, pivot/slicer, внешними ссылками, embedded-объектами, макросами,
подписями и неподдерживаемыми расширениями отклоняются, чтобы не потерять данные.
Для них используйте отдельный дополнительный реестр или специализированный
инструмент с проверкой сохранности. Неизвестная шапка — непроведённая проверка,
а не подтверждение исправности.

Источники возможностей 1С и интеграций проверяются по конкретной версии.
Недоступность ИТС записывается как ограничение; ни установка skill, ни пример
ссылки не дают доступа и не подтверждают механизм. Если в OpenCode нет
разрешённого веб-инструмента, используйте материалы пользователя и не заявляйте
выполненное исследование сайта/ИТС. Детальные карты лежат в references навыка.
