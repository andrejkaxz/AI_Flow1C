# Распространение и готовность к установке

Flow1C `0.1.0-dev.1` распространяется как публичный пилот для Windows/OpenCode.
Другие пользователи могут клонировать продукт, выполнить setup и работать
в пределах готовности выбранного профиля. Стабильный выпуск ещё не объявлен;
версия в `main` меняется, поэтому сохраняйте SHA своей установки.

Собственный код доступен по [MIT License](../LICENSE). Лицензии отдельно
устанавливаемых RLM, BSL Language Server, `cc-1c-skills` и Python-зависимостей
сохраняются; MIT Flow1C не заменяет их условия.

## Объём проверки

Один [Windows CI job](https://github.com/andrejkaxz/AI_Flow1C/actions/workflows/validate.yml)
проверяет Python-регрессии, bootstrap, updater, сохранение пользовательских
настроек и задач, restart/resume, context/handoff, route projections и
guard/OpenCode runtime. Runner использует Python 3.12 и Node.js 22;
updater отдельно запускается в Windows PowerShell 5.1. Поддерживаемый вход
bootstrap — Python 3.10+; CI не является полной матрицей этих версий.

Clean bootstrap и update проверяются в одноразовых внешних fixtures, отдельно
от установки пользователя. Внешние сервисы и проектные данные в регрессиях
заменены синтетическими границами. Успешный CI не подтверждает работу конкретной
модели, корпоративной сети, базы 1С или всех сторонних интеграций.

Для текущего объёма поставки нужны успешный Windows CI выбранного commit,
установка/update с сохранностью состояния и проверки затронутых сценариев.
Linux, дополнительные клиентские матрицы и массовые model evals не являются
условием этого пилота. Их поддержку требуется подтверждать отдельно.

## Приёмка своей установки

1. Клонируйте продукт в новую отдельную папку по [инструкции](pilot-setup.md).
   Для Windows выбирайте короткий путь: известны сбои временных fixtures при
   слишком длинных путях; поддержка произвольной длины не заявляется.
2. Сохраните `git rev-parse HEAD`, версии клиента/модели и выбранный профиль.
   Сверьте [результат CI](https://github.com/andrejkaxz/AI_Flow1C/actions) именно
   для этого commit. Красный или незавершённый CI оставляет проверку открытой.
3. Выполните setup и `doctor --json --profile <профиль>`. Требуется `ready:true`
   для нужного профиля, а не только успешный exit code отдельного шага.
4. Проверьте консультацию, черновик и продолжение после перезапуска на
   разрешённых материалах. Для analysis проверьте реальные источники и RLM.
5. Обновляйте по [update.md](update.md), сохраняя выданные IDs и backup.
   Старые проекты не переносите и не очищайте вручную ради нового layout.

## Известные ограничения

- Основная рабочая среда — Windows/OpenCode. Codex и Claude Code имеют
  адаптеры, но это не подтверждает все сочетания клиентов и моделей.
- Новая база знаний проверена через CLI и guard/runtime contracts.
  Выбор инструмента живой моделью и поиск по большому корпусу ещё требуют
  проверки. Поиск буквальный, без морфологии и семантического индекса.
- Git операции проверяются локально; mock Gitea transport не доказывает
  доступность удалённого сервера или успех PR в вашей установке.
- ZIP без Git checkout не поддерживает обычный update.
- Документы и карточки могут оставаться `UNVERIFIED_DRAFT`; статусы и Git
  commits не заменяют согласование содержания или проверку внедрения.

Отчёт о воспроизводимой проблеме отправляйте в
[Issues](https://github.com/andrejkaxz/AI_Flow1C/issues) с commit, профилем,
клиентом/моделью, ожидаемым и фактическим результатом. Используйте минимальные
синтетические примеры без credentials и материалов заказчика.
