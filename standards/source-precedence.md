# Источники и приоритеты

При анализе и ревью не смешивать источники:

1. Утверждённые бизнес-требования и решения проекта определяют целевое поведение.
2. Исходники типовой конфигурации и БСП определяют фактические имена, типы и точки расширения.
3. ИТС/v8std определяет официальные стандарты.
4. Политика проекта определяет размещение доработок, префиксы и допустимые отклонения.
5. BSL Language Server и SonarQube выдают диагностику, но не заменяют ревью архитектуры и соответствия ФС.
6. Эвристики агента могут быть только рекомендациями с явной маркировкой.

Каждая находка в code review должна указывать тип источника: `business`, `approved-fs`, `project-policy`, `ITS`, `BSL-LS`, `SonarQube` или `heuristic`.
