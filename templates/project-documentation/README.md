# Документация проекта

Положите исходные файлы в подходящую папку и попросите агента выполнить задачу.
Имена файлов сохраняйте понятными: тема, дата встречи или версия документа.

| Что вы хотите передать | Куда положить | Что сказать агенту |
|---|---|---|
| Протоколы, записи и расшифровки встреч, ответы интервью | [Материалы встреч](<Материалы встреч/>) | «Проанализируй материалы встречи по закупкам: выдели решения, требования и открытые вопросы» |
| Шаблон ФС, ТЗ, протокола или инструкции; заполненный образец | [Шаблоны документов](<Шаблоны документов/>) | «Добавь шаблон ТЗ в библиотеку проекта» |
| Excel-реестр процессов и требований | [Реестр процессов и требований](<Реестр процессов и требований/>) | «Импортируй реестр из файла …» |
| Регламенты, инструкции, схемы процессов, существующие ФС и другие документы | [Документы для анализа](<Документы для анализа/>) | «Изучи эти документы и опиши процесс согласования платежей» |

Укажите нужные файлы или подпапку. Если есть несколько версий, скажите, какую
использовать. Можно передать материалы до назначения номера задачи.

Файлы обрабатываются после вашего запроса. Агент сохраняет принятые копии и
ссылки на источники; исходные файлы в этих папках остаются вашими материалами.
Добавление файла само по себе не импортирует реестр, не утверждает шаблон и
не запускает анализ. Поддержку конкретного формата агент проверяет при обработке.

Результат агент показывает со ссылкой на созданный документ. Сохранение изменений
в Git или PR предложит отдельно. Наличие файла не означает, что он уже проверен
или сохранён в Git.

## Служебные папки

`inbox`, `registry`, `work-items`, `drafts`, `requests`, `document-templates`
и `.workspace` обслуживает Flow1C: принятые материалы, индексы, рабочие элементы,
черновики и данные продолжения работы. Для передачи файлов используйте четыре
папки из таблицы. Не переносите и не удаляйте служебные записи вручную.
