# Flow1C

Flow1C — инструменты и правила для аналитиков и архитекторов 1С, работающих
с AI-агентами: интервью, требования, функциональные и технические документы,
анализ XML/BSL и Git, ревью, тестирование и подготовка публикации.

Версия `0.1.0-dev.1` находится в разработке. Публичная готовность ещё не подтверждена.
Репозиторий содержит собственные исходники, правила, шаблоны, тесты и инструкции;
конфигурации 1С и проектные документы подключаются отдельно.

## Начало работы

Откройте корень этого checkout в Codex, Claude Code или OpenCode и попросите:
«Подготовь проект к работе». Выберите профиль; для анализа рекомендуется `analysis`.
Для консультации или независимого черновика достаточно описания в чате.
Такие документы имеют статус `UNVERIFIED_DRAFT`; formal этапы проверяют входы,
версии согласований и evidence. PR согласуют люди.

План настройки без изменения окружения:

```powershell
PowerShell -ExecutionPolicy Bypass -File .\scripts\bootstrap.ps1 -Profile analysis -Plan -Json
```

Для минимального окружения консультаций:

```powershell
PowerShell -ExecutionPolicy Bypass -File .\scripts\bootstrap.ps1 -Profile conversation -Json
.\.venv\Scripts\python.exe scripts\flow1c.py doctor --json --profile conversation
```

`ready: true` подтверждает только проверенный профиль или операцию.
Собственная `.venv` создаётся внутри checkout. Локальные настройки сохраняются
в `.flow1c.local.json`. Секреты передаются через окружение или Credential Manager;
Gitea использует `FLOW1C_GITEA_TOKEN`. [Установка и профили](docs/setup.md).

## Возможности

| Область | Результат |
|---|---|
| Интервью | Вопросы, реестр процессов, ответы и черновые требования |
| Реестр требований | Импорт, проверки связей и impact report |
| Документы | ФС, технический дизайн, разделы Word и пользовательские шаблоны |
| Анализ 1С | Проверка запросов, текущие RLM sources и исторические Git snapshots |
| Разработка и ревью | Контролируемые изменения расширения, diff и BSL diagnostics |
| Завершение | Протоколы тестирования, статусы и подготовка проектных PR |

## OpenCode

Запустите `flow1c-controller`, указанный в `opencode.json`. Продуктовые операции
выполняются инструментами `flow1c_*`. После изменения адаптера перезапустите
клиент и продолжите сохранённый gate. Контроллер обслуживает задачи пользователя;
сопровождение исходного кода описано в [CONTRIBUTING.md](CONTRIBUTING.md).

## Codex

Агент читает корневой `AGENTS.md`, определяет намерение, выбирает основной навык
из `.agents/skills/flow1c-*` и использует CLI gates. Endpoint RLM описан в
`.codex/config.toml`; сервер подключается по выбранному профилю setup.

## Claude Code

`CLAUDE.md` подключает продуктовый `AGENTS.md`. Обёртки `.claude/skills/flow1c-*`
ссылаются на канонические навыки `.agents/skills/`. MCP endpoint описан в `.mcp.json`.
Реальные client/model evals являются отдельной проверкой готовности выпуска.

## ZIP и offline bootstrap

Архив должен содержать весь продукт, включая скрытые каталоги адаптеров.
Git нужен для обновления checkout. Корпоративный wheelhouse задаётся параметром
`-Wheelhouse` с `-NoIndex`; профиль и пути выбираются при setup.
[Порядок установки](docs/setup.md).

## Восстановление прерванной установки

Передайте агенту сохранённый `setup_id` и попросите продолжить.
`setup-status` и `setup-resume` сохраняют шаги и подтверждённые несекретные значения.
Update возобновляется по gate и `update_id`. [Обновление](docs/update.md).
