# Flow1C

**Анализ — легко. Процесс — в удовольствие.**

**Рабочий процесс аналитика и архитектора 1С с AI-агентом: от интервью до документов, ревью и базы знаний проекта.**

[![Windows CI](https://github.com/andrejkaxz/AI_Flow1C/actions/workflows/validate.yml/badge.svg?branch=main)](https://github.com/andrejkaxz/AI_Flow1C/actions/workflows/validate.yml)
[![Python 3.10+](https://img.shields.io/badge/Python-3.10%2B-blue)](docs/setup.md)
[![License: MIT](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)
[![Status: pilot](https://img.shields.io/badge/status-pilot-orange)](docs/distribution.md)

Flow1C — инструменты и правила для аналитиков и архитекторов 1С, работающих
с AI-агентами: интервью, требования, функциональные и технические документы,
анализ XML/BSL и Git, ревью, тестирование и подготовка публикации.

**Версия `0.1.0-dev.1` доступна для пилотной установки. Стабильный выпуск ещё не объявлен.**
Текущий приоритет — работа на Windows/OpenCode и исправление воспроизводимых
пользовательских проблем. CI проверяет Windows, установку/обновление и
сохранность задач. Проверки других сред и моделей выполняются по потребности;
их поддержка этим CI не подтверждается.
Репозиторий содержит собственные исходники, правила, шаблоны, тесты и инструкции;
конфигурации 1С и проектные документы подключаются отдельно.
[Что проверено и как оценивать готовность установки](docs/distribution.md).

## Начало работы

Нужны Windows, Git, Python 3.10+ и установленный AI-клиент. Setup проверит
компоненты выбранного профиля и предложит план установки недостающих.
Текущий CI использует Python 3.12, Node.js 22 и проверяет updater в
Windows PowerShell 5.1.

Клонируйте репозиторий в отдельную папку. Документация проекта, конфигурация 1С
и расширение должны находиться вне этой папки. Для Windows выбирайте короткий
путь: поддержка произвольно длинных путей пока не подтверждена.

```powershell
git clone https://github.com/andrejkaxz/AI_Flow1C.git
Set-Location -LiteralPath .\AI_Flow1C
```

Откройте корень этого checkout в OpenCode и используйте `flow1c-controller`.
Передайте агенту запрос:

> Подготовь проект к работе с профилем analysis. Проведи аудит, согласуй пути
> и план установки, выполни bootstrap, подключение проекта и индексацию.
> Предложи библиотеку шаблонов, сохрани setup_id и покажи итоговый doctor.

Подготовьте идентификатор проекта, папку документации, путь к XML/BSL-выгрузке
конфигурации и папку расширения. Расширение можно подключить как Git checkout
или локальную выгрузку. Шаблоны и реестр требований добавляются при наличии.
В Codex и Claude Code откройте тот же корень и передайте этот запрос.
Для проверки всех возможностей выберите `full` явно; установка `cc-1c-skills`
требует отдельного согласия. Агент проведёт аудит, согласует пути и план установки,
подключит проект и предложит библиотеку шаблонов.
Для пилота используйте [порядок проверки setup](docs/pilot-setup.md).
Материалы встречи, шаблоны, реестр и документы складывайте в соответствующие
папки репозитория документации: [куда положить материалы](docs/project-materials.md).
Для консультации или независимого черновика достаточно описания в чате.
Такие документы имеют статус `UNVERIFIED_DRAFT`; formal этапы проверяют входы,
версии согласований и evidence. PR согласуют люди.

План настройки без изменения окружения:

```powershell
PowerShell -ExecutionPolicy Bypass -File .\scripts\bootstrap.ps1 -Profile analysis -Plan -Json
```

Для минимального окружения консультаций:

```powershell
PowerShell -ExecutionPolicy Bypass -File .\scripts\bootstrap.ps1 -Profile conversation -Json
.\.venv\Scripts\python.exe scripts\flow1c.py doctor --json --profile conversation
```

`ready: true` подтверждает только проверенный профиль или операцию.
Собственная `.venv` создаётся внутри checkout. Локальные настройки сохраняются
в `.flow1c.local.json`. Секреты передаются через окружение или Credential Manager;
Gitea использует `FLOW1C_GITEA_TOKEN`. [Установка и профили](docs/setup.md).

После setup профиля `analysis` проверьте его отдельно:

```powershell
.\.venv\Scripts\python.exe scripts\flow1c.py doctor --json --profile analysis
```

## Профили установки

| Профиль | Состав |
|---|---|
| `conversation` | CLI, консультации, независимые черновики |
| `project-basic` | Предыдущий профиль + Git и подключённый проект |
| `documents` | Предыдущий профиль + Excel/DOCX/PDF |
| `analysis` | Предыдущий профиль + RLM; рекомендуемый старт аналитика/архитектора |
| `implementation` | Предыдущий профиль + BSL Language Server |
| `full` | Предыдущий профиль + `cc-1c-skills` с отдельным согласием |

`full` выбирается явно. Необязательные интеграции устанавливаются по выбранному
профилю; Redmine можно подключить как источник задач и вложений.

| Область | Результат |

| Интервью | Вопросы, реестр процессов, ответы и черновые требования |

| Документы | ФС, технический дизайн, разделы Word и пользовательские шаблоны |
| Анализ 1С | Проверка запросов, текущие RLM sources и исторические Git snapshots |
| Разработка и ревью | Контролируемые изменения расширения, diff и BSL diagnostics |
| Завершение | Протоколы тестирования, статусы и подготовка проектных PR |
| Навигация и знания | Каталог задач/документов, поиск карточек функций, история изменений с источниками |
| Продолжение работы | Сохранённые ответы, setup/update checkpoints, передача завершённого результата |

## Работа с проектом

После подключения откройте README репозитория документации. Новые проекты
получают четыре входные папки: **Материалы встреч**, **Шаблоны документов**,
**Реестр процессов и требований**, **Документы для анализа**. Служебные данные
новых проектов находятся в `.flow1c/`; прежние проекты сохраняют свои пути.

Положите файл в подходящую папку и дайте агенту конкретное поручение:

- «Проанализируй материалы встречи и предложи уточняющие вопросы».
- «Подготовь черновик функциональной спецификации по этому описанию».
- «Найди результаты по согласованию платежей в документации проекта».
- «Что делает эта функция и зачем её изменили? Укажи источники».
- «Обнови каталог результатов проекта».

Файл обрабатывается по запросу. Карточки знаний можно читать из Git или явно
из локальных файлов; сохранение требует поручения пользователя и проверенного
предпросмотра. Карточка и Git commit не подтверждают внедрение в 1С.
[Материалы проекта](docs/project-materials.md) ·
[Результаты и база знаний](docs/project-knowledge.md) ·
[Пользовательские шаблоны](docs/document-templates.md).

## OpenCode

Запустите `flow1c-controller`, указанный в `opencode.json`. Продуктовые операции
выполняются инструментами `flow1c_*`. Для обновления попросите «Обнови Workflow»
или используйте `/update`. Обновлятор сохраняет настройки и состояние задач,
создаёт backup и поддерживает продолжение прерванных шагов.
[Обновление и восстановление](docs/update.md). После изменения адаптера перезапустите
клиент и продолжите сохранённый gate. Контроллер обслуживает задачи пользователя;
сопровождение исходного кода описано в [CONTRIBUTING.md](CONTRIBUTING.md).

## Codex

Агент читает корневой `AGENTS.md`, определяет намерение, выбирает основной навык
из `.agents/skills/flow1c-*` и использует CLI gates. Endpoint RLM описан в
`.codex/config.toml`; сервер подключается по выбранному профилю setup.

## Claude Code

`CLAUDE.md` подключает продуктовый `AGENTS.md`. Обёртки `.claude/skills/flow1c-*`
ссылаются на канонические навыки `.agents/skills/`. MCP endpoint описан в `.mcp.json`.
Наличие адаптера не заменяет проверку конкретного клиента и модели.

## ZIP и offline bootstrap

Для обновляемой установки используйте Git clone. ZIP без Git checkout не
поддерживает обычный update.
Архив должен содержать весь продукт, включая скрытые каталоги адаптеров.
Git нужен для обновления checkout. Корпоративный wheelhouse задаётся параметром
`-Wheelhouse` с `-NoIndex`; профиль и пути выбираются при setup.
[Порядок установки](docs/setup.md).

## Восстановление прерванной установки

Передайте агенту сохранённый `setup_id` и попросите продолжить.
`setup-status` и `setup-resume` сохраняют шаги и подтверждённые несекретные значения.
Update возобновляется по gate и `update_id`. [Обновление](docs/update.md).
